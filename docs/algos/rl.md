# RL fine-tuning of the VLA: Best-of-N and PA-RL (design, decisions, open points)

Status: the code is complete and tested on CPU with fakes (section 7: the YAML defaults and loader; the candidate sampler and cache; the critic network and the replay buffer; the action optimisation; the critic update; the rollouts, the evaluation and the Best-of-N run with its launch script; the distillation, the cache refresh and the PA-RL runs; the re-evaluation of the saved rounds). No full run has been made yet: the cost of each part was measured on the cluster, the whole run was not (section 5). Every value below says where it comes from:
**paper** = Policy Agnostic RL (Mark et al., arXiv 2412.06685v1), with the section / page; **decision** = a choice made for this repository, with its reason, where the paper gives no value or its setting differs (real robot, CALVIN, OpenVLA);
**choice** = a detail the paper leaves open (the table says what was taken); **open** = not settled (section 6).
Rule: the defaults of the YAMLs are the paper's; where the paper has no value, the table gives the value taken and why.

## 1. What is built

Three methods, all on pi0.5 (scope below), all with ONE online-trained critic and UTD = 1, no ensemble, no pessimism (a conservatism bias is likely harmful in an online fine-tuning):

| method | VLA | action executed in rollouts | action executed in evaluation |
|---|---|---|---|
| Best-of-N | frozen | argmax of Q over the k candidates (decision) | same |
| PA-RL, variant A (global) | distilled online | a_t ~ pi^Opt over the top-m (paper, Alg. 2 line 7) | argmax of pi^Opt (paper, B.1; the argmax is a decision) |
| PA-RL, variant B (global + local) | distilled online | same, after T gradient steps on Q | same |

Best-of-N is Algorithm 2 of the paper without the distillation step, restricted to global optimisation (decision). Variant A is "distil after best-of-N, no gradient ascent".
Tactile / force goes to the CRITIC ONLY (the SFT checkpoint is the same for every run and has not learned touch); the comparison is the same algorithm with the critic with and without touch.
Evaluation is the paper's: the VLA WITH action optimisation at inference (so the critic, hence touch, is also used at evaluation). This is a decision: the system is measured as it is deployed.

**Scope: pi0.5 only (decision).** pi0-FAST is not part of these methods, and nothing of the RL code is wired to it. Two reasons measured or read: it decodes greedily as we run it (no sampling temperature is set, see src/models/interface.py), so the k candidates of a state would be identical unless a sampling temperature is added; and 32 candidates cost far too much (about 4 s per state, extrapolated from a probe with synthetic observations, 15 Nov. 2026: about 36 h of model for 1000 episodes of rollouts alone). pi0-FAST stays a baseline of the SFT part (docs/algos/sft.md).

## 2. Algorithm (paper, section 4, Alg. 1 and 2, pp. 7-8)

- Stage I, action optimisation at a state s: sample k actions (chunks) from the VLA; **global**: keep the top m by Q; **local**: T steps `a <- a + alpha * grad_a Q(s, a)` on each kept action, a step being kept only if it
  raises Q (otherwise the loop of that action stops: Alg. 1 lines 5-9). The dataset action is NOT added to the set (decision; the paper includes it in Alg. 1 line 3 but says it is only "sometimes helpful").
- pi^Opt(a|s,m) = softmax over the optimised set of Q (temperature 1) (Eq. 4.3). In evaluation, and in Best-of-N, the argmax.
- Stage II, distillation (PA-RL only): annotate every state of the buffer (warm-up data included, Eq. 4.4) with one action of pi^Opt, and train the VLA on it with its own loss (flow matching for pi0.5: the existing
  `OpenPIPolicy.training_batch` / `loss`). Candidate to imitate: softmax sample or argmax, BOTH paths exist (YAML switch), chosen by the variance of the candidate Q-values (paper B.1, Tables 5-6:
  CALVIN with std 0.02 is better with argmax, the kitchens with std 1.6-11.5 with softmax; no threshold is given). **The standard deviation of the candidates' Q is logged at every iteration** (decision).
- Critic target: the Bellman backup uses actions of pi^Opt at s' (paper, p. 9 and Fig. 16: using the base policy there makes fine-tuning unstable). The VLA's raw candidates of every state are CACHED with the transition
  (paper 5.2.2 and Appendix E); the optimisation (global ranking, local steps) is done on the fly with the current critic. The cache of Best-of-N never expires (the VLA never changes);
  PA-RL recomputes it after every distillation epoch (paper App. E: "the actions cache is updated after every epoch of policy training").
- Loop (Alg. 2, online, no offline data): collect with pi^Opt -> critic updates (UTD 1) -> distillation epoch -> refresh the cache.

### Experiment set: Best-of-N, with and without touch, on the three demonstration types

Two experiment files, `configs/experiment/rl/pi05_best_of_n.yaml` (no touch) and `pi05_best_of_n_touch.yaml` (taxels + measured force in the critic, no proxy), differ only by the critic's touch inputs (`tests/test_rl_config.py` checks it). The SFT checkpoint is a parameter of the job (`--start <SFT run> <step>`): three starting points (the teleoperated, noisy and scripted SFT runs) x two experiments = 6 runs. The run folder defaults to the experiment's `name`, so each run gets its own `--run-name`:

    sbatch jobs/job_rl_best_of_n.sh --start <SFT run> <step> --run-name bon_<demos>
    sbatch jobs/job_rl_best_of_n.sh --experiment configs/experiment/rl/pi05_best_of_n_touch.yaml --start <SFT run> <step> --run-name bon_touch_<demos>

The two experiment files also fix the budget of the study: a warm-up of 600 base-VLA episodes followed by 120 000 critic updates (`warmup_episodes`, `warmup_critic_steps`), then 20 rounds of 50 episodes (`total_episodes: 1000`), with an evaluation of the run (100 fixed episodes) after the warm-up and every 5 rounds (`eval_every_rounds: 5`: rounds 0, 5, 10, 15, 20). `configs/algo/rl.yaml` keeps the paper's values (50 episodes, 5 000 updates, 500 episodes). The two PA-RL experiment files take the same warm-up (600 episodes, 120 000 updates) and keep the rounds of `rl.yaml` (10 rounds of 50 episodes); with the warm-up data in the buffer a PA-RL run takes about 19 h (section 6, item 1), which is why `jobs/job_rl_parl.sh` asks for 24 h. The warm-up budget comes from the tests of Nov. 2026 on the teleoperated demonstrations (150, 300 and 600 episodes with 30 000 to 120 000 updates; evaluations of 500 episodes per round, one run per setting, then 5 seeds of the touch run at 600 episodes / 120 000 updates). A run takes about 6.5 h (calculated: warm-up 142 min, 20 rounds of about 9.7 min, 5 in-run evaluations of about 9 min, saves and server starts), which is why `jobs/job_rl_best_of_n.sh` asks for 8 h.

The server (`robotiq_2f85_tsf`, the default task) sends the taxels, the force and the gripper effort in every run, so the same server serves both experiments.

## 4. Metrics logged at every iteration

Candidate Q standard deviation (mean over states, and the distribution), Q mean / min / max and Q minus the Monte-Carlo discounted return of the visited states (over- and under-estimation, as the paper's Fig. 14), TD loss,
success rate of the rollouts, the share of states where the argmax differs from the VLA's first sample, local optimisation: Q gain, share of accepted steps, L1 norm of the displacement (paper Fig. 13), distillation loss,
Value-estimation error (over- or under-estimation) is a known driver of collapses, so the Q statistics are watched as much as the success rate.

What wandb shows (`rl_metrics` in `src/algos/tracking.py`; `metrics.jsonl` keeps every field and stays the reference). Each key says what it measures and has its own axis:

| section | content | x axis |
|---|---|---|
| `eval/*` | `success_rate` +- `success_se` of the 100 fixed episodes, `steps_mean`, `steps_mean_success`; `eval/opt/*`: the critic's statistics on the states the evaluation visited | round |
| `warmup/*` | the BASE VLA's success rate on the warm-up episodes (`success_rate`, `success_se`): the baseline of the rollout curve | 0 |
| `rollout/*` | the round's own rollouts: `success_rate` +- `success_se`, `online_success_rate_cumulative`, `plans_per_episode`, `env_steps`; `rollout/opt/*`: the same critic statistics as `eval/opt/*`, on the training states | round |
| `critic/*` | loss, `td_loss`, `cal_ql_term`, `grad_norm`, `q_data_*`, `q_candidates_mean`, `q_minus_return` (over- / under-estimation), `candidates_below_vmu_share`, `next_*` (the TD target's action); every window of 500 updates (and the end of each stage), warm-up included | `critic_update` (number of critic updates) |
| `distill/*` | PA-RL: `loss_first` / `loss_mean` / `loss_last`, `grad_norm_mean`, `states`, `steps`, `vla_updates`; `distill/labels/*`: the labels' statistics | round |
| `refresh/*`, `buffer/*`, `time/*` | cache refresh size, buffer size, seconds per phase | round |

The `opt/*` statistics (the same names for rollouts, evaluation and labels): `candidate_q_std_{mean,p10,p50,p90}` (the spread of Q among the k candidates: 0 = the critic cannot rank), `candidate_q_mean`, `optimised_q_mean`, `chosen_q_mean`, `chosen_q_gain_mean` (chosen minus the mean candidate: what the critic expects to gain), `chosen_shift_l1_mean` (L1 distance, over the chunk and in the normalised space, between the chosen chunk and the VLA's first sample: how far the critic moves the action) and `chosen_differs_from_first_sample_share` (about 1 - 1/k for Best-of-N, so only a sanity check: the two above are the informative ones); PA-RL with local steps: `local_q_gain_mean`, `local_accepted_share`, `local_displacement_l1_mean`. Left out of wandb: constants (episode counts, round ids), the loop's own step counter, copies of the same wall time, the per-collection lines of the warm-up, the critic's mean over a whole round (the windows are the finer curve).

|---|---|---|---|
| pi0.5 | 1 x 1 | 101 ms | 101 ms |
| pi0.5 | 8 x 1 | 678 ms | 85 ms |
| pi0.5 | 50 x 1 | 4 319 ms | 86 ms |
| pi0.5 | 1 x 32 | 159 ms | 159 ms |
| pi0.5 | 8 x 32 | 1 529 ms | 191 ms |
| pi0.5 | 50 x 32 | out of memory (30 GiB asked, 24 GiB available) | - |

- pi0.5: 32 candidates per state cost little more than the state itself (the prefix is computed once; 159-191 ms against 85-101 ms). The images' prefix is the floor (about 85 ms per state, about 5 h over the whole refresh even with one candidate).
  Calls of 50 environments x 32 samples do not fit: the rollouts split them (`rows_per_sample_call = 8` in `configs/algo/rl.yaml`, so 7 calls of 8 for 50 environments). One round of 50 episodes: about 182 s of model (19 plans x 50 x 191 ms) + about 97 s of simulator = about 280 s, so about 0.9 h of collection for a run of 10 rounds of 50 episodes with the warm-up (estimate).
- Cache refresh of pi0.5 (every state of the buffer after every round except the last: 51 300 recomputations for a run of 10 rounds of 50 episodes at 19 plans per episode): 195 ms per state measured (the model alone 190 ms), so about 2.8 h. The first extrapolation, for 1000 episodes and a refresh after every round, gave 9.6 h (calls of 1 row) to 11.6 h (calls of 8 rows). Decision: full refresh as the paper (section 3).
- Distillation: 960 steps at 9.3 s = about 2.5 h (measured per step). Critic updates (UTD 1: 80 000 updates per run with the warm-up, upper bound: every episode at 150 steps): MEASURED on 15 Nov. 2026 (`scripts/probe_critic_cost.py`, job 11722567, L40S, synthetic data): Best-of-N and PA-RL A 77.8 ms per update (38.9 host batch + 38.9 device), B 79.9 ms (the local ascent costs 2 ms: the MLP only); peak memory of the critic 1.6 GB; the card is used about 6 %, the host assembly of the batch (numpy) is half of the time, which is why the batches are prepared ahead (next bullet). Each update also ranks (and, in B, optimises) the 32 candidates of 256 next states.
- Measured 15 Nov. 2026 (`scripts/probe_parl_cost.py`, pi0.5 LoRA, L40S, JAX limited to half of the card, micro-batch 4): distillation step 9.3 s, annotation 0.2 ms per state, refresh 195 ms per state, saves 10 s (5.9 GiB), peak 22.3 GiB. Two exact speed-ups are in the code: the last round's refresh is not made (nothing reads it), and the critic's batches are prepared by a thread while the previous update runs (`run_updates(prefetch=3)`: the same batches, the same training bit for bit (`tests/test_rl_critic_update.py`); measured 44.7 ms per update in the loop against 78.9 one after the other; `probe_critic_cost` prints `overlapped_ms`). Whole PA-RL run of 10 rounds of 50 episodes (+ 50 warm-up), at 19 plans per episode (upper bound): 960 distillation steps 2.5 h, 51 300 refreshed states 2.8 h, 80 000 critic updates 1.0 h, collection 0.9 h, 3 evaluations 0.4 h = about 7.5 h (about 5 h at 10 plans per episode), plus saves and server starts; Best-of-N about 2.5 h (collection, critic updates, evaluations).
- PA-RL stage costs (annotation per state, distillation step, refresh per state, saves, memory of the VLA + Adam + critic) come from `scripts/probe_parl_cost.py` (job `jobs/job_probe_parl_cost.sh`: the real pi0.5 of an SFT checkpoint, synthetic states, no simulator, minutes), which measures each per unit with the code of the run and prints an estimate of the whole run (the collection, evaluation and critic hours are constants from the measurements above).

## 6. Cost decision and open points

1. Cost of a run: the target is under 10 h in total. With the 1000 episodes of the paper the measured pieces add up to 23.8 h for PA-RL (section 5), so the budget is 10 rounds x 50 = 500 online episodes (+ 50 warm-up), `total_episodes: 500`: 960 distillation steps (2.5 h), 51 300 refreshed states (2.8 h), 80 000 critic updates (1.0 h), 0.9 h of collection, 0.4 h of evaluations (rounds 0, 5, 10) = about 7.5 h at 19 plans per episode (upper bound), about 5 h at 10, plus saves and server starts; Best-of-N about 2.5 h. The same budget applies to every method (the comparison). Not measured end to end. With the study's warm-up (600 episodes, 120 000 critic updates, `warmup_episodes`) the warm-up data is distilled and refreshed in every round, so the PA-RL pieces grow (calculated from the measured unit costs, 19 plans per episode): distillation 166 250 states over the 10 rounds = 2 598 steps = 6.7 h; refresh after rounds 1 to 9 = 145 350 states = 7.9 h; critic updates 120 000 + about 64 000 = 2.3 h; warm-up collection 1.0 h, online collection 0.8 h, evaluations (rounds 0, 5, 10) 0.45 h: about 19 h, plus saves and server starts.
2. The SFT checkpoint each run starts from (`--start <SFT run> <step>`): not fixed in the experiment files.
3. Memory margin: the distillation peaks AT the JAX limit with micro-batch 4 (section 7, item 7); micro-batch 2 is the fallback. The memory of a collection server on top of the learner is not measured.
4. First PA-RL probe (variant B, 2 rounds of 50 episodes, 500 warm-up updates, 16 Nov. 2026, 2 h 04 instead of the ~1 h expected): the whole chain ran (distillation 9.6-9.9 s per step, refresh 202 ms per state, VLA checkpoints, evaluation of the distilled VLA), but (a) the critic's updates went from 0.041 s to about 0.56 s each, abruptly at the first distillation + refresh and steadily after (a main run would then take about 15 h: over the 12 h limit); the learner process sat at the JAX limit (23 340 MiB at 0.5 of the card), which is the leading hypothesis and is NOT confirmed; (b) the distilled VLA of round 2 evaluated at 9 % against 22 % at round 0 (paired, McNemar p = 0.002), but with the critic's argmax and the local ascent on top of a critic still far from converged (Q still falling, gradient norms 10-35 after the refresh, local displacement 10x larger): the evaluation of the VLA alone (`scripts.eval_rl --selection vla`) and a second probe (variant A, 5 000 warm-up updates, `XLA_PYTHON_CLIENT_MEM_FRACTION=0.6`) decide. A second probe (variant A, 5 000 warm-up updates, fraction 0.6, 17 Nov. 2026, 1 h 14) removed the slowdown (20-21 s per 500 critic updates in every stage) and showed the VLA alone still falling with the distillation (42 -> 32 -> 21 % at rounds 0, 1, 2; the critic's argmax 30 -> 25 -> 14 %) although the labels' Q gain is small (0.36-0.40 for a candidate std of 0.28: nearly the VLA's own samples). The control `distill_selection: first` (label = the VLA's own first candidate, no critic) tells the process's damage from the labels': `--set distill_selection=first` on the settings of that probe, then `scripts.eval_rl --selection vla`. No main run of PA-RL before it.
5. `tests/test_openpi_policy.py` (the checks of `sample_candidates`, `normalized_to_targets` and `training_batch_from_normalized` against the real transforms) needs the `vla` group and has to be run on the cluster.

Settled (section 3): the budget of 500 episodes (10 rounds of 50; 1000 in the paper, cut for cost) with one distillation epoch per round, which critic ranks (Q_theta) and evaluates (Q_bar), the critic's inputs and touch (the repo's convention), the distillation recipe, the code stack (JAX / Flax) and the cache refresh policy (full).

## 7. Implementation (one component at a time, each with its tests)

1. YAML defaults (`configs/algo/rl.yaml`, one experiment per method in `configs/experiment/rl/`) and their loader (`src/algos/rl_config.py`, `tests/test_rl_config.py`). The SFT checkpoint each run starts from (`start: {run, step}`) is not in the experiment files: it is given by `--start`.
2. candidate sampler and cache (`src/algos/rl_candidates.py`, `tests/test_rl_candidates.py`; `OpenPIPolicy.sample_candidates` / `normalized_to_targets` and `Candidates` in `src/models/`, checked against the real transforms in `tests/test_openpi_policy.py`, which needs the `vla` group and was NOT run here).
   - The critic and the local ascent work in the model's NORMALISED chunk space (first 8 dimensions of the model output, before the output transforms): `sample_candidates` returns those chunks with the state rows, `normalized_to_targets` brings a chunk (chosen or moved) back to the env's space to be executed or distilled.
   - `CandidateSampler`: pi0.5 in calls of `rows_per_sample_call` = 8 environments, every call padded to 8 (one compilation).
   - `CandidateCache`: by state id, with the version of the VLA that drew the candidates (Best-of-N: one version for ever; PA-RL: a new one after each distillation epoch; `stale_ids`), `refresh` recomputes them reading the buffer in chunks, with seeds that are a function of (seed, state id, version). About 16 KiB per state for pi0.5 (20 000 states: about 330 MB).
3. critic network and replay buffer (`src/algos/rl_critic.py`, `src/algos/rl_buffer.py`, `tests/test_rl_critic.py`, `tests/test_rl_buffer.py`; JAX / Flax, tested on CPU). The network: `q_values(net, params, state, actions)` gives Q of N chunks per state (a state is encoded once), the target is a delayed copy (`soft_update`), touch is a switch of the config. The buffer: one row per state, the rows of an episode contiguous (the next state of row i is row i + 1, the ids are the candidate cache's), reward -1 per plan and 0 at success (the only terminal), V^mu = Monte-Carlo return-to-go of every episode, a time-out (any end without success) bootstraps from its last state (`needs_candidates`), batches that mix warm-up and online rows by `mixing_ratio`. About 300 KB per state (about 3.3 GB for the 550 episodes of a run, allocated lazily).
4. action optimisation (`src/algos/rl_action_opt.py`, `tests/test_rl_action_opt.py`; JAX, tested on CPU on a toy critic with closed-form answers, then on the real network at small size). `ActionOptimiser(encode, score, keep_top, local_steps, local_lr)` (`for_critic(net, cfg)`): global top-m by Q of the k cached candidates, then T steps of `a <- a + alpha * grad_a Q` per kept chunk, a step kept only if Q rises strictly (a NaN / inf Q is refused). The ascent is deterministic, so "stop the loop of this action" (Alg. 1) and "refuse every non-rising step" give the same result and the code does the latter, with no per-action mask. `pick(result, mode, rng, temperature)` is pi^Opt: softmax sample or argmax of the optimised set (the mode is `rollout_selection`, `distill_selection` or `eval_selection`; the caller gives the rng). Best-of-N = keep_top 1, no local step, argmax. The critic was split into `rl_critic.encode_state` (CNNs, once per state) and `rl_critic.score` (MLP), so the T + 1 evaluations of the ascent run the MLP only: without that, a critic update of 256 states would re-run the CNNs on 512 images at every ascent step (about 150 000 updates per run). `summarise` gives the section 4 metrics (candidate Q std mean / p10 / p50 / p90, Q gain, accepted share, L1 displacement, share of states where the chosen chunk differs from the VLA's first sample). The selection mode that produces the a' of the TD target is set by the critic update (item 5): `rollout_selection`, the paper-faithful reading (a sample of pi^Opt).
5. the critic update (`src/algos/rl_critic_update.py`, `tests/test_rl_critic_update.py`, `scripts/probe_critic_cost.py`, `tests/test_probe_critic_cost.py`, `jobs/job_probe_critic_cost.sh`; JAX, tested on CPU). `CriticTrainer.update(batch)`: y = r + gamma * (1 - terminal) * Qbar(s', a') with a' from `ActionOptimiser` + `pick(rollout_selection)` under the CURRENT critic, loss = MSE TD + cal_ql_alpha * (mean_k max(Q(s, a_k), V^mu) - Q(s, a_data)) with a_k the cached candidates of s, then Adam and `target <- tau * params + (1 - tau) * target`, all in one jitted step. `make_batch` draws the transitions with the mixing ratio and looks the candidates of s and s' up in the cache (a success is terminal: it has no candidates at s', its own are borrowed and the value is masked; a time-out's last state has them). `run_updates(trainer, buffer, cache, rng, steps)` is the loop (the batches are prepared ahead by a thread, `prefetch=3`, with the same random draws in the same order: the training is bit-identical to the serial loop): the warm-up is `steps = warmup_critic_steps` once the warm-up episodes and their candidates are stored; online the caller asks for `utd * environment steps` per round. Metrics returned: loss, TD, Cal-QL term, grad norm, Q mean / min / max on the data actions, Q minus the Monte-Carlo return, candidates' Q mean and std, share of candidates under V^mu, target mean, and for the next states the candidates' Q std and (variant B) the local Q gain and accepted share. Tests: loss and target recomputed by hand, terminal / time-out, the delayed copy, and a critic that learns the values of a four-state chain. The warm-up episodes themselves (50 episodes of the base VLA) are collected by step 6.
6. rollouts, evaluation and the Best-of-N run (`src/algos/rl_rollout.py`, `src/algos/rl_run.py`, `scripts/rl.py`, `jobs/job_rl_best_of_n.sh` and `jobs/job_rl_parl.sh --variant A|B` (one job per method; `tests/test_rl_jobs.py` checks the arguments they pass), `tests/test_rl_rollout.py`, `tests/test_rl_run.py`, `tests/test_rl_script.py`, doubles in `tests/rl_fakes.py`; CPU, with a fake VLA and fake environments that follow the protocol).
   - `RLActor.act(obs, ..., mode)`: the VLA's k candidates (the cached ones: nothing is sampled twice), then `"vla"` (the first candidate: the warm-up), `"softmax"` (PA-RL's rollouts) or `"argmax"` (Best-of-N's, and every evaluation); the critic's batch is padded to K rows (one compilation), the chosen chunk goes back to the env's space with `normalized_to_targets`. `OptimisingPolicy` wraps it behind the `plan` of the SFT evaluations, so `src/eval/episodes.run_batch` plays the evaluation unchanged (same starts, same episode seeds, same per-plan noise).
   - `collect_round`: K episodes of one server from `reset(seed, round)`, a new chunk every `replan` steps (half the chunk, as the evaluations), until they have all ended; records the state seen at every plan and the last state (the TRUE final observation `next_obs()`), the chunk executed in the normalised space, the candidates of the T states (T + 1 for a time-out, whose last state is bootstrapped from: one extra model call), the steps each episode lasted (the UTD counts them).
   - `RLRun` (the stage = the warm-up, then one round with its critic updates): warm-up of `warmup_episodes` base-VLA episodes + `warmup_critic_steps` updates; per round, collection with the method's `rollout_selection`, then `utd` x (environment steps) updates, then the evaluation when scheduled. Best-of-N never refreshes the cache (the VLA never changes).
   - Resume: after each stage, in this order, `episodes/stage_<r>.npz` (episodes + candidates), `resume/critic_<r>.msgpack` (critic, delayed copy, Adam; named by stage since step 7, so a crash while it is written never mixes two stages), `resume/state.json` (the stage, the update count, the random generators): the stage is finished only when that file says so, and the resume files of every other stage are then removed. `--resume` rebuilds the buffer and the cache from the episode files and continues; a cut stage is played again from its start. Tested: a run stopped after round 1 and resumed ends with the same critic, optimiser state, buffer and evaluation hashes as an uninterrupted one. The critic of EVERY round (11 files for 10 rounds, about 20 MB each) is kept in `critics/round_<r>.msgpack`, so any round can be evaluated later; PA-RL keeps the VLA's trainable parameters of every round too (step 7); each evaluation is `eval/results/<round>.json` in the format of the SFT evaluations (the curve and `scripts/compare_eval_paired.py` read it).
   - `scripts/rl.py --experiment <file> --start <SFT run> <step>`: the model, LoRA and normalisation statistics are the SFT run's (the statistics are compared byte for byte with the checkpoint's copy); pi0-FAST is refused; `--dry-run` prints the plan; `--resume <run>` accepts no change of the run's settings but the logging. wandb gets the `round`, `warmup` and `eval` lines (x axis = round) and the critic's lines every 500 updates, the warm-up's included (`critic/*`, x axis = `critic_update`, the number of critic updates); the log and `metrics.jsonl` have them too.
   - XLA's deterministic GPU ops are NOT switched on in a run (the flag is global to the process and would slow the critic's training); the in-run evaluation has the same starts and seeds as the SFT ones but is comparable, not bit-reproducible, like them (the cameras are not either).
   - Not measured end to end: the time of the whole run and the memory of a collection server on top of the learner. The job limits are 6 h for Best-of-N (about 2.5 h estimated) and 24 h for PA-RL (about 19 h estimated at most with the 600-episode warm-up, section 6 item 1); the per-unit costs of PA-RL (annotation, distillation, refresh, memory of the VLA + Adam + critic) were measured (section 5).
7. distillation (pi0.5) and the cache refresh, PA-RL variants A and B (`src/algos/rl_distill.py`, `src/algos/rl_run.py`, `src/models/openpi_policy.py`, `src/algos/rl_candidates.py`, `scripts/rl.py`; `tests/test_rl_distill.py`, `tests/test_rl_run.py`, `tests/test_rl_candidates.py`, `tests/test_rl_script.py`, the trainable fake VLA of `tests/rl_fakes.py`; `tests/test_openpi_policy.py` has a new test of `training_batch_from_normalized` that needs the `vla` group and was NOT run here).
   - Stage r >= 1 of a PA-RL run: collection with `rollout_selection` (softmax) under the VLA of version r - 1 -> critic updates (`utd` x environment steps) -> DISTILLATION -> REFRESH -> VLA checkpoint -> commit (the evaluation after round r then runs the new VLA with the new critic's argmax). The warm-up (stage 0) distils nothing: the evaluation of round 0 is the SFT checkpoint with the critic. The cache version of a state is the round whose VLA drew its candidates (0 = the SFT checkpoint); after every refresh all of them have the version of the round (checked, the run stops otherwise).
   - Annotation (`Distiller.annotate`): EVERY stored state that has cached candidates (the states of the plans and the last state of a time-out, warm-up included) gets one action of pi^Opt under the critic as it is at the end of the round's updates (`ActionOptimiser` + `pick(distill_selection)`, the same code as the rollouts; the labels are fixed for the round). The labels stay in the model's NORMALISED space and are the training targets as they are (`OpenPIPolicy.training_batch_from_normalized`: the observation takes `training_batch`'s path, the chunk goes into the first 8 dimensions, the rest is zero padding; no round trip through the env's space, which would lose information).
   - Training (`VLATrainer`): the recipe of `src/algos/sft.py` (its functions are reused, its loop is copied and the SFT is not touched): openpi's AdamW and clipping from `configs/algo/sft.yaml` with the learning rate `distill_lr` constant (no warm-up, no decay), batch `distill_batch_size` in micro-batches of `distill_micro_batch_size`, the draws of a step made once for the whole batch, trainable parameters in float32, frozen ones in bfloat16, `distill_epochs` epochs over the annotated states with a new order each epoch (the incomplete tail is dropped), Adam's state kept from round to round. Memory: the step frees its gradient trees as the SFT does (donated running sum, names dropped), and `distill_micro_batch_size` is 4 (the SFT's is 16): at 16 and at 8 the first step ran out of memory (the SFT's LoRA peak at 16 is about 24 GiB, JAX is limited to 22.3 GiB, half of the L40S, the env server has the rest). `scripts/probe_parl_cost.py` asks the compiler for the memory of each micro-batch (16, 8, 4, 2; `memory_analysis()`, nothing is run) and uses the largest that fits. Result (probe of 15 Nov. 2026, pi0.5 LoRA; resident 13 GiB): need 21.9 GiB at 16, 22.3 at 8 (do not fit), 21.1 at 4, 20.4 at 2. At 4 the pass ran (about 9.3 s per step, annotation 0.2 ms per state) with a peak AT the limit (23.96 of 23.96 GB): no margin, so 4 is the default and 2 the fallback. After the epochs the policy runs the weights as deployed (everything bfloat16: what the SFT evaluations do) and the cache is refreshed with them (`refresh`: all the candidate states, reading the buffer in chunks, seeds a function of (seed, state id, version)).
   - Files: `resume/cache_<r>.npz` (the cache with its versions: the refresh is hours of model calls and is never recomputed on a resume), `resume/vla_<r>/` (trainable parameters + Adam, the SFT's snapshot writer), and `vlas/round_<r>/` (the trainable parameters as an SFT checkpoint: `params/` + `meta.json` with the round, the update count, the variant, the SFT start, + the normalisation statistics; `sft.load_checkpoint` reads it on a policy of the same model YAML) kept for every round (about 1.7 GB each, about 17 GB per PA-RL run of 10 rounds). The checkpoint is written before `state.json`. `--resume` rebuilds the buffer from the episode files, then loads the cache, the VLA and Adam, the generator of the batch order and the version, and ends exactly as an uninterrupted run (tested with the fake VLA: VLA, Adam, cache with versions, critic and generators equal; after the warm-up alone too).
   - Logged: `distill` (the labels' statistics = the candidates' Q std, the Q gain and the accepted share of variant B, the share of labels that differ from the VLA's first sample; the states, the steps, the loss first / mean / last, the gradient norm, the times) and `refresh` lines per round, `refresh_progress` every 5 % in `metrics.jsonl` only; wandb gets the first two.
   - A stop (SIGTERM) is honoured between stages: a PA-RL stage is the collection + the updates + the distillation + the refresh, hours at the end of a run; a signal during it waits for its end (the time limit of the job must leave room for that: the jobs send the SIGTERM 5 minutes before the end, which is far from enough for a late PA-RL round: a run that hits the limit during a stage loses that stage and `--resume` plays it again).
   - Not measured: the whole run, and the memory of a collection server on top of the VLA + its float32 trainable copy + Adam + the critic on one card (the learner alone peaks at 22.3 GiB). `tests/test_openpi_policy.py` has to be run on the cluster (it needs the `vla` group).
8. re-evaluation of the rounds of an RL run, as the SFT checkpoints are evaluated (`scripts/eval_rl.py`, `jobs/job_eval_rl.sh`, `tests/test_eval_rl_script.py`; CPU, with the model, the sweep and the servers replaced, on run folders written by the real `RLRun` with the fakes).
   - `python -m scripts.eval_rl --run <RL run> [--rounds 0 5 10 ...]`: round r = the critic `critics/round_<r>.msgpack` + the VLA `vlas/round_<r>/` (PA-RL, r >= 1) or the SFT checkpoint the run started from (Best-of-N, and round 0); only rounds the run finished (`resume/state.json`) and whose files are complete are offered. The policy is the run's own (`OptimisingPolicy`: the k candidates, the optimisation of the method, variant B's local ascent included, the critic's argmax).
   - Same machinery as `scripts/eval_sft.py` (imported, not copied: the SFT script is untouched): `Sweep` (a FRESH env server per round, `--envs-per-server` 100, `--workers`, resume at the episode, SIGTERM), master seed 42 and the episode seeds of the SFT evaluations (same starts, same seeds, so SFT curve, in-run evaluations and this one are comparable), XLA deterministic GPU ops, the lock, `--dry-run`, `--plot-only`, `--force`, `--save-videos`, the protocol file that refuses another model / task / replan / seed in the same folder. Results in `<run>/eval_rl/results/<round>.jsonl` + `.json` (the SFT format: `curve.py`, `compare_eval_paired.py`), x axis = the collection round. The folder is NOT the run's `eval/` (evaluations made during the run, `<round>.json` only, no determinism flag): the two never mix.
   - Normalisation statistics: the file of the SFT run's model YAML, compared byte for byte with the copy in EVERY VLA checkpoint to evaluate (the SFT start's and each `vlas/round_<r>/assets/`, written by `save_norm_stats`); a difference is refused. The RL computes none.
   - What differs from the SFT evaluation, by necessity: the model is called as the run calls it (`rows_per_sample_call` environments x k candidates per call, padded: one compilation) instead of K rows split by `--model-batch`; the settings of the candidates / optimisation / critic of the run (`variant`, k, keep_top, local steps, `eval_selection`, the critic's inputs) are part of the folder's protocol (`rl` block, checked). A warning is printed when the task YAML + the run's `env_set` differ from the task the run was made with.
   - `jobs/job_eval_rl.sh`: a separate job (L40S, requeueable, no mail: not a training job), time limit 6 h = a margin (11 rounds at about 8 min: not measured for the RL policy). The determinism flag makes a re-evaluation comparable with another one; it does not make it equal to the in-run evaluation of the same round (different flag, other shapes: same starts and seeds, a standard error apart).
